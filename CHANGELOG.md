# История изменений

Новые выпуски — сверху. Раздел версии целиком становится описанием выпуска на GitHub (`scripts/github_export.py release`).
Подробности функций — в [README.md](README.md).

## 0.4.0.5 — 12.11.2026

### Изменено

- «Настройки программы» — как в оригинале: дерево разделов с квадратными значками и жёлтым выделением, шапка над деревом,
  заголовок страницы, группы с синими заголовками, подписи слева от полей в одну строку; окно открывается компактным
  (около 720×520) и меняет размер.
- «Свойства информационной базы», «Добавление информационной базы», окна группы и «Выбор группы» — в том же оформлении:
  наименование в отдельной строке, страница в рамке, подписи в одну колонку, компактный блок платформы.
- Общее оформление диалогов компактнее: шрифт диалогов по умолчанию 12 (сохранённый размер не меняется), поля ниже,
  флажки и переключатели без цветной заливки, выключенные поля и подписи заметнее.
- Пояснения со страниц перенесены во всплывающие подсказки (открываются и при переходе по Tab) и в «Краткую справку»;
  F1 в настройках и свойствах базы открывает справку на нужном разделе. Предупреждения о потере данных остались на страницах.
- Сообщение внизу окна — в одну строку, полный текст по кнопке «Подробнее…»; страница при этом не прыгает.
- При крупном шрифте поля переносятся под подпись, длинные значения укорачиваются «…» с полным текстом в подсказке;
  минимальный размер окон растёт вместе со шрифтом.

### Исправлено

- Страницы свойств базы открываются сверху при переключении разделов (раньше сохранялась прокрутка прежней страницы).
- Серверная база с полным номером версии в записи (`Version=8.3.27.1859`) при общем правиле «8.3» запускалась новейшим
  клиентом, и 1С сообщала, что вход невозможен: версии клиента и сервера различались. Теперь общее правило, как правило ветки
  и 1CEStart, не заменяет полный номер версии записи. Ключ `/AppAutoCheckVersion-` передаётся только для правила одной сборки
  (`8.3.27.2214`): при правиле семейства или релиза 1С сама выбирает клиент под версию сервера.
- Путь ручного клиента, оставшийся в настройках после переключения на «Подбирать установленную версию», больше не
  запускается вместо выбранной версии. Ключ проверки версии, вписанный в параметры запуска, не повторяется. Колонка
  платформы у вручную выбранного клиента показывает его релиз, а если он не определяется — «—».
- Колесо мыши над закрытым списком, полем даты или числа больше не меняет значение (например, режим прокси при прокрутке
  страницы), а прокручивает страницу. Открытый список и календарь листаются, как раньше.
- Escape при открытом календаре, списке или меню закрывает только его. Раньше Escape в календаре на странице «Блокировка»
  закрывал всё окно свойств, и несохранённые правки терялись.
- Надпись «Есть неприменённые изменения настроек» пропадает, если вернуть прежнее значение.
- Предупреждение «Версия клиента не определена» в настройках платформы больше не повторяется дважды.

### Исправлено

- `Ctrl+F4` на базе веб-сервера открывал окно параметров конфигуратора, а запуск затем завершался ошибкой. Теперь клавиша
  сразу сообщает, что конфигуратор к веб-базе не подключается.
- Windows: `--update` и `--rollback` из командной строки не могли заменить работающий файл программы («Нет доступа») — с
  0.3.0.8. Обновление окном и фоном это не затрагивало. Сама 0.4.0.3 из командной строки по-прежнему не обновится — обновите
  её окном (Настройки → «Обновление») или фоном; дальше командная строка работает.

## 0.4.0.3 — 07.11.2026

### Изменено

- Обновление программы больше не требует GitHub CLI (`gh`): проверка и загрузка выпусков идут напрямую по HTTPS из
  публичного репозитория, без входа. Прокси — системный (Windows) или из переменной `HTTPS_PROXY` (Linux). Загруженный
  архив сверяется с контрольной суммой GitHub и с `SHA256SUMS.txt`, как и раньше проходит пробный запуск. Загрузку
  останавливает только отмена или 60 секунд без данных — медленная, но живая связь доводит её до конца.
- `gh` остаётся запасным путём: если GitHub не ответил по HTTPS (нет связи, лимит запросов, закрытый «другой репозиторий»),
  программа пробует `gh`; если не удалось и так — одно сообщение с причинами.
- Настройки → «Обновление»: описание источника выпусков исправлено.

### Как обновиться с 0.4.0.2 и раньше

- Если `gh` установлен и выполнен вход — программа обновится сама, как обычно.
- Без `gh` прежние версии обновиться не могут: один раз закройте программу и распакуйте архив этого выпуска поверх её
  папки (настройки и список баз не затрагиваются). Дальше обновления идут без `gh`.

## 0.4.0.2 — 07.11.2026

### Новое

- Свойства и добавление базы: внизу окна, как в оригинале, — путь к файлу списка `.v8i`, к которому относится база (для
  базы общего списка — путь к общему списку). Длинный путь сокращается многоточием, полный — во всплывающей подсказке.
  Щелчок или Enter/пробел открывают файл в текстовом редакторе, как «Сервис → Список ИБ ▸ Открыть в редакторе»; если
  файла нет или открыть не удалось — сообщение в окне. Для локального списка в настройках программы строки нет.

### Изменено

- Окно создания и подключения базы: кнопка справа от строки соединения теперь «Вставить строку соединения», как в оригинале.
  Она берёт из буфера обмена строку вида `Srvr="…";Ref="…";` (или `File="…";`, можно с префиксом `Connect=`) и заполняет
  размещение базы; строка с другими параметрами (СУБД, сервер и имя базы данных…) сохраняется целиком как изменённая.
  Скопировать строку можно выделением и Ctrl+C.
- Свойства базы, «Дополнительные параметры» — как в оригинале: поле всегда доступно, флажка «Использовать параметры общего
  списка» больше нет. Строка сохраняется в записи базы в списке `.v8i` (`AdditionalParameters`) и действует также при запуске
  из стартера 1С; очищенное поле удаляет ключ. Строка, сохранённая прежними сборками в настройках программы, показывается в
  поле и переносится в список при сохранении свойств; до этого список не меняется. Для списка только для чтения строка
  по-прежнему хранится в настройках программы (под полем — пояснение). Если строка содержит код `/UC`, под полем
  предупреждение: его увидят все, кто открывает список.
- Кнопка «…» в поле «Дополнительные параметры» открывает окно «Параметры запуска 1С:Предприятие 8» со справочником ключей;
  «Продолжить» переносит строку в поле, ничего не запуская. У поля «Внешняя обработка» вместо кнопки «Выбрать…» —
  «…» внутри поля (так же и в окне «Запуск с параметрами»).
- Сообщение об отменённой загрузке обновления короче — «Загрузка версии … отменена»: прежнее обрезалось в строке
  состояния узкого окна.

### Исправлено

- Создание базы: после отмены или остановки по времени временная папка журнала 1С удаляется и тогда, когда остановленный
  процесс освобождает её с небольшой задержкой; прежде сообщение «Создание отменено.» могло получить лишнее замечание
  «Временная папка журнала 1С не удалена» о папке, которая через мгновение была уже свободна.
- «Завершение процессов "1С:Предприятие 8"»: процесс проверяется и завершается через одну и ту же ссылку на него (в Linux —
  pidfd), поэтому номер, освободившийся и выданный другому процессу в этот момент, не завершит чужой процесс. Если надёжную
  ссылку получить нельзя (старое ядро Linux), процесс не завершается и называется в строке состояния.

## 0.4.0.0 — 25.10.2026

Первый стабильный выпуск ветки 0.x: перенесённые функции StartManager проверены вместе сквозными сценариями на Windows и Linux
и прошли полный независимый аудит кода.

### Важно при обновлении

- **Сохранённые пароли версий 0.3.0.x удаляются** при первом запуске 0.4.0.0. Пароли теперь привязаны не только к ID базы, но
  и к списку баз, в котором она записана: база с тем же ID в другом списке чужой пароль не получает. Старые записи не
  переносятся, чтобы пароль одного списка не достался базе другого. При первом открытии окна программа один раз сообщает
  отдельным сообщением, у скольких баз удалены пароли («Сохранённые пароли прежней версии удалены у баз: N — введите их заново
  в свойствах»); введите их заново в свойствах базы, страница «Аутентификация». При запуске без окна (`--no-gui`) это сообщение выводится отдельной строкой.
- Возврат на 0.3.0.x («Восстановить версию») удалённые пароли не возвращает.

### Новое

- **Резервирование**, как в оригинале:
  - сценарии резервирования: наименование, описание, шаблон имени файла с макросами, до трёх каталогов, формат DT, CF или ZIP;
    сверх оригинала — сжатие и тома ZIP, «Хранить копий»; три готовых сценария и основной сценарий; разделы настроек
    «Сценарии резервирования» и «Параметры резервного копирования», страница свойств базы «4. Резервное копирование»;
  - выгрузка: DT и CF через конфигуратор в пакетном режиме (файловые и серверные базы), ZIP файлов файловой базы; копии во
    второй и третий каталоги, журнал выгрузок, удаление старых копий; окно «Выполнение сценария» с проверкой занятости базы,
    кнопкой «Установить блокировку ИБ» и окном хода с отменой;
  - загрузка: DT, CF (с обновлением конфигурации базы данных), ZIP с откатом при сбое; окна «Список выгрузок» и «Загрузка
    данных»; перед загрузкой DT/CF сохраняется страховочная копия файлов базы;
  - меню «Свойства ▾»: «Выгрузить резервную копию данных…» (Shift+Ctrl+F5), «Загрузить данные из резервной копии…»
    (Shift+Ctrl+F7), загрузка базы из `.dt` и конфигурации из `.cf`;
  - импорт сценариев и настроек резервирования из StartManager.
- **Блокировка базы для выгрузки** ставится со случайным кодом доступа и снимается после выполнения; код передаётся 1С
  ключом `/UC` и в журналах скрыт. Блокировка, установленная пользователем, используется как есть и не снимается.
- **Ярлык программы в меню приложений Linux**: Настройки → «Общее» → «Меню приложений» или ключи `--install-desktop` /
  `--uninstall-desktop`. Повторное создание обновляет путь к программе, удаление убирает только свои файлы.
- **Индикатор загрузки обновления**: этапы «Загрузка… N из M МБ», проверка контрольной суммы, распаковка, пробный запуск; загрузку
  можно отменить. При способе «Загружать автоматически» ход виден в строке состояния.
- Сбой автоматической проверки обновлений (например, `gh` не вошёл в GitHub) виден в строке состояния, а не только в журнале.

### Исправлено

- На Linux при коде выхода 255 у 1С без графического сеанса — понятное сообщение вместо одного кода.
- Общий список на сетевой папке: понятные сообщения о занятом файле (Linux) и об отказе сетевой папки в имени или пароле
  (Windows); оставшаяся отметка завершённой записи убирается при чтении.
- Снимки и импорт читают списки в памяти, без временных `.v8i`; журналы создания базы — в частной временной папке.
- Дублирование не публикует копию базы, которая изменилась во время копирования; сбой окна выбора папки не завершает программу.
- Загрузка из ZIP возвращает файл данных под именем `1Cv8.1CD` и отказывает архиву с двумя вариантами написания.
- Неизвестные поля настроек аутентификации сохраняются, в том числе записанные другим окном.
- «Отсутствующие конфигурации» на Linux удаляют каталог конфигурации целиком, как обещает вопрос.
- Если помощник восстановления или установки обновления не запустился при старте, программа об этом сообщает и повторяет
  попытку при следующем запуске.
- Отменённая команда не показывается как «Команда не выполнена».
- Восстановление снимка, совпадающего со списком, ничего не записывает, и следующая внешняя правка не принимается за прерванную
  запись.
- Уведомление об обновлении стоит в строке состояния перед описанием списка.
- Разделы настроек открываются с начала; подписи дерева разделов переносятся только между словами; поля даты и времени страницы
  «6. Блокировка» вмещают значение при крупном шрифте.
- Окно «Выполнение сценария»: Escape во время выполнения ведёт себя как закрытие окна, состояние блокировки показывается точнее.
